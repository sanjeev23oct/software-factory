A factory changes who decides what gets built, who checks it, and what gets recorded. You approve the requirements before anything is built, a separate agent checks the work, and every check leaves evidence behind. |
| 6 | 1:15 | 16s | Agents write all the code | The definition I like best comes from Dru Knox, at Tessl. A software factory is any agentic system where agents write all of the code you ship. Which means your job changes. You stop building the product... and you start building the machine that builds it. |
| 7 | 1:31 | 18s | Autonomy first | So how do you know if your factory is any good? Knox uses three measures, and the order matters. First, autonomy. How often does a person have to step in and nudge the agents? Then automation. How much can you let run without anyone reviewing it? And then quality. You earn automation, by proving autonomy first. |
| 8 | 1:49 | 14s | Verification makes it safe | And what makes autonomy safe? Verification. You can only stop reading every line if something else is checking it. Every time. And leaving a record you can actually inspect. Without that, honestly, a factory is just a faster way to ship mistakes. |
| 9 | 2:03 | 22s | Three loops | Now, a factory runs in three loops. The inner loop is where agents iterate before anything goes up for review. It's fast, and it's cheap. The outer loop is the slower, thorough checking, the kind that replaces your review time. And then there's the meta loop. That one watches the corrections and the failures... and fixes the factory itself, so the same mistake doesn't happen twice. |
| 10 | 2:25 | 14s | Eleven stages: agents write, scripts check, a person approves twice | Okay. Here's the factory I built, on top of Claude Code. It has eleven stages. Agents write the requirements, the plan, and the code. Scripts do everything that can be checked mechanically. And a person steps in exactly twice. |
| 11 | 2:39 | 16s | The pipeline is data: who does each stage, and how | And here's the thing. The whole pipeline is just data. Each stage says who does the work, an agent, a script, or a human, which skill it follows, and what it's allowed to write. If a stage fails three times, the factory stops, and asks a person. |
| 12 | 2:55 | 17s | A skill: how one kind of job is done | Every kind of job has a skill. It's just a short, written instruction. This one's for UI logic. Pure functions, no DOM, no clock. And look at the last line. The maker never ticks its own task, and never writes its own evidence. |
